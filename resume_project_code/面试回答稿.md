## 2. HTTP 服务器（推荐重点背诵）

**问：为什么用 epoll？**  `select/poll` 每次都要遍历 fd 集合，复杂度和 fd 数量相关；epoll 在内核维护就绪队列，适合大量连接。我使用非阻塞 socket 和 ET 模式，事件到来后循环 `recv`，直到返回 `EAGAIN`。

**问：一次请求怎么处理？** 监听 socket 收到连接后 `accept`，设置非阻塞并加入 epoll；IO 线程读取到 `\r\n\r\n` 后解析请求行和头部，把业务任务放进线程池；工作线程读取并构造响应，最后发送并关闭连接。正式版本应把连接状态和待发送缓冲区保存下来，以支持真正的异步写和 keep-alive。

**问：如何处理半包/粘包？**  TCP 没有消息边界，所以每个连接保留输入缓冲区。未找到完整头部就继续读；找到头部后按 `Content-Length` 判断请求体是否完整；处理完一条请求后保留剩余字节，继续解析下一条。

**问：线程池怎么保证安全？** 任务队列由 mutex 保护，条件变量唤醒空闲线程。提交任务时加锁入队并通知；工作线程等待“停止或队列非空”，析构时设置停止标志、广播并 join。队列满时应限制长度并采取拒绝、阻塞或降级策略。

**问：如何防止路径穿越？** 拒绝包含 `..` 的路径，并将请求路径与 web 根目录做规范化后的前缀校验；只允许常规文件，不能直接拼接后无校验地读取。

**问：怎么测试？** 先用 curl 做功能测试，再用 wrk/ab 做并发测试，记录并发连接数、吞吐、P95 延迟和错误率。简历中没有经过完整压测的数据时，我会明确说“目前是功能验证，性能数据待补测”，不会虚报数字。

**问：如何排查内存增长？** 先看 RSS 和连接数是否同步增长，再用 ASan/LeakSanitizer、valgrind、heaptrack 定位分配栈；检查任务队列、连接对象、缓存和异常路径是否释放。

## 3. 两轮平衡小车

**问：控制结构？** 传感器提供姿态，编码器提供轮速；定时器以固定周期执行姿态融合、速度计算和控制输出。通常采用串级 PID：内环快速控制俯仰角，外环慢速控制速度，转向量叠加到左右轮差速。

**问：加速度计和陀螺仪区别？** 加速度计能由重力估计绝对倾角，但受振动和运动加速度影响；陀螺仪短期响应快但积分会漂移。因此用互补滤波或卡尔曼滤波融合。

**问：抖动怎么调？** 先固定采样周期并检查机械、电源和传感器零偏，再看原始角度和控制输出；减小内环比例/微分或增加滤波，确认没有积分饱和，最后逐步调参并记录响应曲线。

**问：如何保证实时性？** 中断只做采样、置标志和轻量计算；复杂日志、显示和通信放到主循环/任务中。若控制计算超过周期，就降低计算量、提高周期或拆分任务，否则会造成相位延迟和振荡。

## 4. Qt + OpenCV 人脸识别

**问：为什么多线程？** UI 线程只负责窗口和显示，摄像头读取、图像预处理、检测/识别放到 worker 线程，通过 Qt 信号槽传回结果，避免界面卡顿。跨线程不直接操作控件，必要时使用 queued connection 和深拷贝图像。

**问：处理速度跟不上怎么办？** 降低输入分辨率或检测频率、限制队列长度并丢弃过期帧；检测和识别分级处理，复用模型和内存，避免每帧重复创建对象。

**问：识别流程？** 采集人脸样本并保存元数据，训练/加载模型，实时帧先做人脸检测，再提取特征并与数据库中的用户特征匹配，超过阈值才判定为已知身份。光照、姿态和遮挡会影响结果，需要规范采集和阈值验证。

**问：摄像头断开怎么处理？** 检测 `read` 失败，发出错误信号，释放设备并在 UI 提示；重连要设置退避，避免死循环占满 CPU。

## 5. STM32 智能风扇

**问：DHT11 怎么读？** 主机先拉低并释放数据线，等待传感器响应；随后按时序读取 40 位数据，校验湿度整数/小数、温度整数/小数和校验和。读取应有超时，失败时保留上次有效值并上报错误。

**问：中断、PWM 和按键？** 定时器提供固定调度节拍，外部中断或定时器捕获红外脉宽；PWM 占空比控制电机平均电压。按键采用定时采样和软件消抖，模式切换用显式状态机，OLED 刷新降频，不能阻塞控制任务。

## 6. C/C++/Linux 基础回答

- `malloc/free` 只分配原始内存；`new/delete` 还负责构造和析构，必须配对。
- `vector` 连续内存、随机访问快；`list` 插入删除稳定但缓存局部性差，不能默认认为更快。
- mutex 保护临界区；条件变量用于等待条件；信号量适合计数资源。加锁顺序固定、缩小临界区可降低死锁风险。
- 进程地址空间隔离、创建成本较高；线程共享地址空间但需要同步。常见 IPC 有 pipe、FIFO、共享内存、消息队列和 socket。
- GDB 常用 `run`、`bt`、`frame`、`info locals`、`watch`；段错误先看回溯和非法指针，再用 ASan 复现。
- 网络字节序是大端，使用 `htons/ntohs/htonl/ntohl`；TCP 提供可靠字节流，HTTP/1.1 通常运行在 TCP 之上。

- **问：工作线程很慢怎么办？** 限制单任务耗时和队列长度，拆分慢任务或异步化；必要时返回过载状态，不能无限堆积内存。
