## 二、项目一：基于 STM32 的两轮平衡小车控制系统（2026.02 - 2026.04）

**技术关键词：** C、STM32、六轴姿态传感器、双路编码器、串级 PID、PWM 电机控制、闭环控制。

### 项目介绍

这个项目的目标是让两轮小车实时保持直立，并完成定速巡航、转向和基本运动控制。系统以 STM32 为主控，采集六轴姿态传感器和左右轮编码器数据，经过姿态估计、速度计算和串级 PID 后，输出左右电机 PWM 控制量。

我负责六轴姿态传感器数据采集和车体倾角解算、双路编码器测速和反馈、姿态环与速度环组成的串级 PID、左右轮 PWM 合成输出，以及平衡、定速巡航和转向调试。简历中提到的“优化响应速度和运行稳定性”，面试时要结合真实的调参过程和测试现象说明。

### 系统数据流

固定控制周期内依次完成：读取加速度和角速度；姿态融合得到俯仰角和角速度；读取左右编码器增量并计算轮速；速度环生成姿态修正量；姿态环生成平衡输出；将转向量叠加到左右轮，限幅后更新 PWM。可概括为：左右轮输出 = 平衡控制量 + 速度修正量 ± 转向控制量。实际工程还要处理传感器异常、编码器溢出、PWM 限幅和倒地保护。

### 为什么使用串级 PID？

内环是快速姿态环，负责纠正倾角、防止小车倒下；外环是较慢的速度环，负责前进、后退和定速巡航。把两个时间尺度不同的目标分开后，姿态稳定和速度控制不会相互争夺同一个输出，调参和定位也更清晰。内环频率应高于外环，但具体数值要按实际控制周期测量，不能凭空填写。

### 加速度计、陀螺仪和姿态融合

加速度计静止时可利用重力估计倾角，但运动和振动会干扰它；陀螺仪短期响应快，但积分会因零偏漂移。因此使用互补滤波或卡尔曼滤波：高频变化更多参考陀螺仪，低频趋势用加速度计校正。先做零偏校准和坐标轴方向确认，再将融合角度送入姿态环。

### 编码器测速和跑偏处理

在固定采样周期内读取左右编码器增量，结合每圈脉冲数、减速比和轮径换算轮速。左右轮增量平均值用于车体速度，差值用于转向和左右补偿。需要处理计数器溢出、正反转方向、采样周期抖动和线缆噪声。跑偏时先检查左右电机和编码器方向，再做软件补偿，不能只改 PID。

### 抖动或突然倒下如何排查？

先检查重心、轮胎、支架、电机供电和传感器固定；再记录原始角度、角速度、编码器数据、控制周期和 PWM 波形。高频抖动通常检查比例过大、微分噪声和滤波；慢慢跑偏检查左右电机差异、编码器方向和零点；突然倒下检查控制周期丢失、传感器异常、积分饱和和输出限幅。

### 如何保证实时性？

定时器提供稳定节拍，中断只做采样、计数、置标志和轻量计算；OLED、日志和非关键通信放到低优先级任务。控制计算必须在周期内完成，否则会增加相位延迟。如果超时，先减少重复计算和非关键刷新，再考虑拆分任务。面试时需要补充实际主控型号、传感器型号、控制周期和滤波方法。

## 三、项目二：高性能 HTTP 服务器（2026.05 - 2026.06）

**技术关键词：** C++、线程池、epoll、LRU、DJB2、双向链表、哈希表。

### 项目介绍

这是一个 Linux 下的高性能静态 HTTP 服务器。它使用 epoll 做 IO 多路复用，使用非阻塞 socket 管理客户端连接，再用线程池异步处理 HTTP 请求和静态资源响应，支持图片、视频等静态资源。

我主要完成：基于 epoll 实现事件驱动 IO；实现 HTTP/1.1 请求解析，支持 GET、标准状态码和静态资源请求；设计线程池和任务队列，避免 IO 线程被文件处理阻塞；实现文件读取、类型识别和数据返回，并针对大文件设计缓冲区。简历列出的 LRU、DJB2、双向链表和哈希表，应说明它们在缓存或索引中的真实接入位置；若只是模块实验，要明确边界。

### epoll、ET 和一次 GET 请求

select/poll 需要反复遍历 fd 集合；epoll 返回就绪事件，更适合大量连接。非阻塞 socket 在 ET 模式下收到可读事件后必须循环 recv，直到 EAGAIN/EWOULDBLOCK。请求流程是：accept 新连接并加入 epoll；连接可读时把数据追加到独立输入缓冲区；找到 `\r\n\r\n` 后解析请求行、请求头和 URL；将任务放入线程池；工作线程做路径检查、文件查找、MIME 判断和响应构造；通过写缓冲发送，部分 send 后保留偏移并监听 EPOLLOUT。

### 半包、粘包和 keep-alive

TCP 是字节流，不保证一次 send 对应一次 recv。每个连接保存独立输入缓冲区；未找到完整头部就继续接收；有 Content-Length 时判断请求体是否收全；解析完一条只消费已处理字节，剩余字节继续解析。keep-alive 需要保存读写缓冲、解析状态、请求数和最后活动时间；响应发送完重新监听 EPOLLIN，超时或协议错误时关闭。若当前实现是短连接，要明确说这是简化版本。

### 线程池如何保证安全？

线程池由工作线程、任务队列、互斥锁、条件变量和停止标志组成。提交任务时加锁入队并通知；工作线程等待“队列非空或停止”，取出任务后解锁再执行；析构时设置停止标志、广播并 join。队列必须有上限，满时拒绝、阻塞或返回 503，不能无限堆积。

### LRU、DJB2、双向链表和哈希表

静态资源缓存可以用哈希表按 URL 快速定位节点，用双向链表维护访问顺序：命中后移到表头，容量不足从表尾淘汰。DJB2 可用于 URL 或文件名哈希，再配合冲突处理定位缓存项。面试时还要说清缓存对象、容量、文件修改后的失效策略及并发锁；如果没有完整接入主流程，就说“完成模块和实验验证，主链路集成测试待补”。

### 路径安全、大文件和测试

限制请求行/请求头/请求体大小，拒绝 `..` 等非法路径；规范化绝对路径后检查其仍在 web 根目录内，并确认是普通文件。大文件采用固定缓冲区或 mmap/sendfile 分段传输，send 部分写出时保留偏移。用 curl 覆盖首页、图片、视频、404、非法路径和大文件，再用 wrk/ab 测吞吐、P95 延迟、错误率、CPU、内存和队列长度。简历没有给出 QPS，必须使用真实压测数据或说明待补测。

### MySQL 和识别质量

DHT11 读取流程是主机拉低并释放数据线，等待响应，再按脉宽读取 40 位数据：湿度整数/小数、温度整数/小数和校验和。每一步要有超时；校验失败保留上一次有效值并设置故障标志。红外接收可用外部中断记录边沿、定时器测脉宽，再按实际协议解析引导码、地址码、命令码和重复码。PWM 由硬件定时器输出，占空比负责调节电机速度。

## 六、C/C++、Linux 高频基础题

- **`malloc/free` 与 `new/delete`：** 前者只分配和释放原始内存；后者还负责构造和析构，必须配对，数组使用 `new[]/delete[]`。
- **`vector` 与 `list`：** vector 连续存储、随机访问快、缓存友好；list 已知迭代器位置插入删除为 O(1)，但节点分散且有额外指针开销。没有明确需求通常优先 vector。
- **mutex、条件变量、信号量：** mutex 保护临界区；条件变量等待条件；信号量表示资源数量。固定加锁顺序、缩小临界区并用 RAII 降低死锁风险。
- **进程、线程和 IPC：** 进程地址空间独立、隔离好；线程共享地址空间、切换成本低但需要同步。IPC 有 pipe、FIFO、共享内存、消息队列和 socket。
- **GDB 与内存工具：** 用 `bt`、`frame`、`info locals` 定位崩溃；ASan 查越界和 use-after-free，LeakSanitizer/Valgrind 查泄漏。
- **网络字节序和 TCP：** 网络序为大端，使用 `htons/ntohs/htonl/ntohl`；TCP 是可靠字节流，应用层必须自行处理消息边界。

## 十一、C 语言基础题

### 1. 指针和数组有什么区别？

数组是一段连续的内存，数组名在大多数表达式中会退化为首元素指针，但数组本身不是指针。`sizeof(array)` 得到整个数组大小，`sizeof(pointer)` 只得到指针大小。函数传数组时通常需要额外传长度。

### 2. `const`、`static` 和 `volatile` 的作用？

`const` 表示通过该标识符不能修改对象；`static` 在函数内表示保持生命周期，在文件级表示限制符号的链接范围；`volatile` 告诉编译器变量可能被中断、硬件或其他执行流修改，不能随意优化掉访问。`volatile` 不能替代锁，也不能保证原子性。

### 3. 什么是野指针和悬空指针？

未初始化或指向未知地址的指针是野指针；指向已经释放对象的指针是悬空指针。解决方法是初始化为 `nullptr`，明确所有权，释放后立即置空，并使用 RAII、智能指针或容器管理生命周期。

### 4. 栈和堆有什么区别？

栈由编译器自动管理，分配释放快但空间有限，适合局部变量和调用上下文；堆由程序管理，空间更大但需要处理释放、碎片和线程安全。嵌入式中还要关注栈溢出和静态内存占用。

### 5. 什么是内存对齐？

CPU 按特定边界访问数据更高效，编译器可能在结构体成员之间插入填充字节。可以用 `sizeof` 和 `offsetof` 验证布局；网络协议或硬件寄存器映射不能直接假设 C 结构体布局，应明确字节序、长度和对齐。

### 6. `memcpy` 和 `memmove` 的区别？

两者都复制字节，但源和目标区域重叠时只能使用 `memmove`；`memcpy` 在重叠场景下行为未定义。复制对象时还要确认是否包含指针、是否需要调用构造函数，不能把 C++ 非平凡对象当字节块随意复制。

### 7. 什么是宏的风险？

宏在预处理阶段展开，没有类型检查，可能产生重复求值、优先级和命名冲突问题。常量优先使用 `constexpr`，小函数优先使用 `inline`，必须使用宏时给参数和整体加括号。

## 十二、C++ 基础与面向对象

### 1. 封装、继承和多态是什么？

封装把数据和操作放在类中并隐藏实现；继承用于复用和建立类型关系；多态让基类接口在运行时调用派生类实现。实际工程中优先组合而不是深层继承，接口要小而稳定。

### 2. 构造函数、析构函数和拷贝控制？

构造函数建立对象不变量，析构函数释放资源。若类拥有文件句柄、锁或堆内存，需要正确实现或禁用拷贝，并考虑移动构造和移动赋值。现代 C++ 通常遵循 Rule of Zero，使用容器和 RAII 避免手写资源管理。

### 3. 虚析构函数为什么重要？

通过基类指针删除派生类对象时，如果基类析构函数不是虚函数，可能只调用基类析构，导致资源泄漏或未定义行为。只要类有虚函数并可能被多态删除，通常就应提供虚析构函数。

### 4. `override`、`final` 和纯虚函数？

`override` 让编译器检查是否真的重写了基类虚函数；`final` 禁止继续重写或继承；纯虚函数使类成为抽象类，派生类必须实现该接口。它们能把设计意图交给编译器检查。

### 5. `unique_ptr`、`shared_ptr` 和 `weak_ptr`？

`unique_ptr` 表示唯一所有权，不能拷贝但可移动；`shared_ptr` 使用引用计数管理共享所有权；`weak_ptr` 不增加引用计数，用于观察对象并打破循环引用。默认优先 `unique_ptr`，只有确实需要共享所有权时使用 `shared_ptr`。

### 6. 左值、右值和移动语义？

左值通常有稳定身份，右值多为临时对象。移动构造可以“窃取”临时对象的资源，避免深拷贝；移动后对象仍需保持可析构、可赋值的有效状态。使用 `std::move` 只是类型转换，不会自动移动资源。

### 7. `map`、`unordered_map` 和 `set` 怎么选？

`map` 通常是平衡树，键有序，查找 O(log n)；`unordered_map` 基于哈希，平均查找 O(1)，但要考虑哈希冲突和扩容；`set` 只保存唯一键。需要有序遍历用 map，需要快速键查找且不关心顺序可用 unordered_map。

### 8. 异常安全有哪几个等级？

基本保证是失败后对象仍处于有效状态；强保证是操作失败时状态不变；不抛出保证表示操作不会抛异常。资源管理使用 RAII，先构造临时对象再交换，可以较容易实现强保证。

## 十三、数据结构与算法基础题

### 1. 常见复杂度怎么比较？

常见顺序是 O(1)、O(log n)、O(n)、O(n log n)、O(n²)。回答复杂度时同时说明平均和最坏情况，例如哈希表平均查找 O(1)，极端冲突时可能退化；快速排序平均 O(n log n)，最坏可到 O(n²)。

### 2. 链表反转怎么���？

维护 `prev`、`cur` 和 `next` 三个指针，先保存后继，再把当前节点指向前驱，最后依次推进。时间复杂度 O(n)，额外空间 O(1)。实现时要特别处理空链表和单节点。

### 3. 栈和队列的应用？

栈是后进先出，适合括号匹配、函数调用和 DFS；队列是先进先出，适合任务调度、BFS 和生产者消费者。HTTP 线程池中的任务队列就是典型的并发队列场景。

### 4. 二叉树遍历？

前序是根左右，中序是左根右，后序是左右根，层序使用队列。二叉搜索树中序遍历可得到有序序列，但普通二叉树不具备这一性质。

### 5. 排序算法怎么选？

数据量小或接近有序可考虑插入排序；需要稳定排序可用归并或稳定的库排序；一般场景使用标准库 `sort`，不要为了手写算法忽略边界、比较器和性能验证。面试写题时先说明复杂度和稳定性要求。

### 6. 如何判断链表有环？

使用快慢指针，慢指针每次走一步，快指针每次走两步；如果相遇则有环。时间 O(n)，空间 O(1)。要找环入口，可以在相遇后把一个指针放回头结点，两者同步前进再次相遇的位置就是入口。

### 7. 二分查找的边界？

先明确查找的是任意命中、第一 个大于等于目标，还是最后一个小于等于目标，再确定区间是闭区间还是半开区间。循环不变量比死记模板更重要，要测试空数组、一个元素和目标在边界的情况。

## 十四、Linux 与操作系统基础题

### 1. 用户态和内核态是什么？

用户态权限受限，应用通过系统调用请求内核服务；内核态可以访问硬件和内核数据。socket、文件读写、epoll 和线程调度都会涉及系统调用。频繁系统调用会有上下文切换成本，因此要合理批量读写。

### 2. 进程创建和 `fork` 的特点？

`fork` 创建子进程，父子进程拥有独立的虚拟地址空间，通常通过写时复制减少初始复制成本。父进程要通过 `wait/waitpid` 回收子进程，否则可能产生僵尸进程。

### 3. 什么是上下文切换？

CPU 从一个执行流切换到另一个执行流，需要保存和恢复寄存器、栈等上下文。线程切换通常比进程切换轻，但频繁创建线程、锁竞争和过多任务仍会降低性能。

### 4. 死锁的四个必要条件？

互斥、占有且等待、不可剥夺和循环等待。工程上可通过固定加锁顺序、一次申请全部资源、缩短临界区、使用 `try_lock` 或超时机制来降低风险。

### 5. 虚拟内存和页面缺失？

虚拟内存给每个进程提供独立地址空间，页表把虚拟地址映射到物理页。访问尚未装入内存的页面会触发缺页异常，由内核调入；频繁换页会导致抖动，表现为 CPU 不高但程序很慢。

### 6. 常用 Linux 排查命令？

`ps/top` 查看进程和 CPU，`free/vmstat` 查看内存，`ss/lsof` 查看端口和连接，`df/du` 查看磁盘，`strace` 查看系统调用，`perf` 做性能采样，`gdb` 调试崩溃。排查时先确认现象和时间范围，再选择工具，不要无目的地堆命令。

### 7. 文件描述符是什么？

文件描述符是进程中指向内核打开文件对象的整数句柄，socket、管道和普通文件都可以用 fd 表示。fd 有进程上限，连接泄漏会耗尽 fd；因此必须在所有错误和退出路径关闭或转移所有权。

## 十五、计算机网络基础题

### 1. TCP 三次握手和四次挥手？

三次握手用于确认双方收发能力并同步序列号：客户端 SYN，服务端 SYN+ACK，客户端 ACK。关闭连接通常需要双方分别发送 FIN，因此常见为四次挥手；TIME_WAIT 用于让旧报文过期并保证最后 ACK 可重传。

### 2. TCP 可靠性如何实现？

通过序列号、确认应答、超时重传、滑动窗口、校验和和拥塞控制实现可靠传输。TCP 可靠不代表应用层消息完整，HTTP 仍需要自行定义请求边界。

### 3. 流量控制和拥塞控制区别？

流量控制关注接收方处理能力，避免发送过快压垮接收方；拥塞控制关注网络整体状态，避免大量数据造成拥塞。TCP 接收窗口和拥塞窗口共同限制发送量。

### 4. HTTP 常见状态码和方法？

GET 获取资源，POST 提交数据，PUT 通常整体更新，DELETE 删除；2xx 表示成功，3xx 表示重定向，4xx 表示客户端请求问题，5xx 表示服务端问题。静态服务器只实现 GET 时，要明确这是项目范围选择。

### 5. HTTP/1.1 和 HTTPS？

HTTP/1.1 是应用层协议，通常运行在 TCP 上；HTTPS 是 HTTP 加 TLS，提供加密、完整性和服务器身份认证。HTTPS 会增加握手和加解密成本，但可通过连接复用、会话恢复等方式优化。

### 6. DNS、ARP 和 NAT？

DNS 把域名解析为 IP；ARP 在局域网中把 IPv4 地址解析为 MAC 地址；NAT 在不同地址空间之间转换 IP/端口。它们解决的是不同层次的问题，不要把 DNS 说成负责连接建立。

### 7. 什么是粘包？

粘包不是 TCP 出错，而是 TCP 字节流没有消息边界。解决方法是在应用层设计长度字段、固定长度、分隔符或自描述格式；HTTP 使用请求行、头部结束符、Content-Length 或 chunked 等规则确定边界。

## 十六、数据库与 SQL 基础题

### 1. 主键、唯一键和索引？

主键唯一标识一行且通常不允许为空；唯一键保证列值唯一；索引是辅助查找结构，能加速查询但会增加写入、存储和维护成本。不是所有列都应该建立索引。

### 2. 事务的 ACID？

原子性表示事务要么全成功要么全失败；一致性表示事务前后满足约束；隔离性表示并发事务相互隔离；持久性表示提交结果能够保存。回答隔离级别时要能说出脏读、不可重复读和幻读。

### 3. SQL 注入如何防止？

不要拼接用户输入生成 SQL，使用预编译参数绑定；对输入做长度、格式和权限校验；数据库账户遵循最小权限原则。日志中也不要泄露密码等敏感字段。

### 4. `JOIN` 和分页？

`INNER JOIN` 只保留匹配行，`LEFT JOIN` 保留左表全部行。小数据可用 LIMIT/OFFSET，深分页时 OFFSET 会越来越慢，可使用基于索引键的游标分页。

### 5. 人脸项目如何设计表？

用户表至少包含用户 ID、姓名、创建时间；样本或特征可放独立表，通过 user_id 关联，并对查询字段建立合适索引。图片、模型等大对象是否直接存数据库要结合大小、备份和部署要求决定。

## 十七、嵌入式与 STM32 基础题

### 1. 中断和轮询怎么选？

轮询实现简单但可能浪费 CPU 或错过短脉冲；中断响应及时，适合按键、外部边沿和定时事件，但中断服务函数必须短小，不能在其中做阻塞、复杂打印或长时间计算。

### 2. 定时器常见用途？

定时器可产生周期中断、输出 PWM、输入捕获脉宽、测量时间间隔和驱动软件调度。配置时要说明时钟频率、预分频、自动重装值以及最终计数周期之间的关系。

### 3. PWM 频率和占空比？

频率决定一个周期的快慢，占空比决定高电平在周期内的比例。电机调速通常通过改变占空比实现平均电压调节；频率要避开可听噪声、驱动器限制和过高开关损耗，具体值应以电机和驱动器手册为准。

### 4. I2C、SPI、UART 区别？

I2C 两根线、支持地址寻址和多设备共享，但速度和时序相对复杂；SPI 通常全双工、速度快，但需要片选线；UART 异步、点对点、布线简单。姿态传感器、OLED 和调试串口可根据实际模块接口选择。

### 5. 看门狗有什么用？

看门狗在程序长期没有按时喂狗时复位系统，用于应对死循环、任务卡死和严重异常。它不能代替错误处理，喂狗应放在确认关键任务正常运行之后，而不是在任意循环里无条件喂。

### 6. 如何降低嵌入式功耗？

减少无效轮询和高频刷新，让 MCU 进入合适的睡眠模式；按需开启外设时钟，降低传感器和显示刷新频率；使用中断唤醒。降低功耗不能破坏控制周期和安全响应，需要实测电流与唤醒延迟。

## 十八、Qt 与 OpenCV 基础题

### 1. Qt 事件循环是什么？

Qt 事件循环负责分发鼠标、键盘、定时器、网络和跨线程信号等事件。UI 线程被耗时任务阻塞时，事件无法及时处理，表现为窗口卡顿，因此视觉计算要放到 worker 线程。

### 2. `QObject` 为什么不能随意跨线程？

QObject 有线程归属，子对象通常跟随父对象。把对象移动到线程后，槽函数和事件会在目标线程处理；不能让多个线程直接操作同一个 QWidget，销毁顺序也要先停任务、再退出线程、最后释放对象。

### 3. `QImage` 和 `cv::Mat` 转换注意什么？

两者都可能只保存外部数据指针，转换时要确认步长、像素格式和底层缓冲区生命周期。若原始 Mat 很快被复用或释放，应调用 `copy()` 做深拷贝，避免显示花屏或访问已释放内存。

### 4. OpenCV 图像预处理常见步骤？

按模型要求进行颜色空间转换、灰度化、缩放、裁剪、归一化、降噪或直方图处理。预处理必须和训练阶段一致，否则模型输入分布变化会降低识别效果。

### 5. 如何评价识别系统？

除了准确率，还应关注精确率、召回率、误识别、漏识别、单帧延迟和连续运行稳定性。测试集要覆盖不同光照、角度、距离和遮挡，不能只用注册时的同一批图片测试。

## 十九、面试答题模板

遇到基础题可以按四步回答：

1. 先给定义或结论；
2. 解释为什么，最好联系简历中的项目；
3. 说明边界条件、异常情况或复杂度；
4. 如果没有实际做过，明确说理解原理但尚未在项目中验证。

例如被问“为什么线程池队列要设上限”，可以回答：“队列上限用于限制内存和等待延迟。没有上限时，突发流量会无限堆积，最终拖垮服务；达到上限后可以拒绝、阻塞或返回 503。我的 HTTP 服务器中，任务队列的具体上限和压测结果需要按实际测试补充。”
